# ADR-0012：控制台页面用零构建静态目录，挂在同源 `/`

日期：2026-10-21
状态：**已被 ADR-0016 取代**（零构建与源目录直服作废；同源挂载、API 之后挂载、缺目录不挂三条继续有效）
相关：`frontend/{index.html,app.css,app.js}`、`app/main.py`、
`tests/test_api/test_m6_api.py`（末尾两条静态挂载用例）、ADR-0011（后台化与任务进度）

## 背景

M0–M6 交付的是一条纯 JSON 的 API：上传简历、发起出题、轮询任务、读报告。要"用起来的"
人（维护者自己、以及拿它做真实面试的同事）只能对着 `curl` 和 `/docs` 操作，而这条链路
的体验恰恰依赖一个非同步的东西——图在后台跑 80 秒，中间要一路看 `parse → validate → …`
的步序、回退轮和最终批注。缺一个能点的东西。

约束是这台机器给定的：没有 Docker、没有 `make`、没有 `uv`，Node 只在工具链里，
项目历史上也没有任何前端构建步骤；测试基线要求离线且 `create_app()` 可反复调用。

## 决策

1. **不引入构建工具与任何依赖**。新增 `frontend/` 一个静态目录，三个文件
   （`index.html` / `app.css` / `app.js`），原生 ES + `fetch`，零 CDN、零 npm 包、零打包步骤。
2. **同源挂载，不做跨域**。`create_app()` 在 `include_router` **之后**
   `app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True))`。顺序是硬要求：
   Starlette 按注册顺序匹配，`/` 排在前会把 `/api/v1/...` 全吃掉。
3. **目录不存在就不挂**。`if FRONTEND_DIR.is_dir()`——`StaticFiles(check_dir=True)`
   缺目录会直接抛错，而 `create_app()` 抛错等于整条 API 测试套件的连坐。
4. **页面只做展示与轮询，不承载任何判断**。配额、评分、质量门、证据核对全在服务端；
   客户端唯一的"逻辑"是按 `task.status` 分支轮询（2 秒一次，`completed`/`failed` 停）
   和把报告摊成 DOM。所有来自简历/JD/模型的文本一律经 `esc()` 转义后再进 `innerHTML`。
5. **导出 Markdown 在浏览器里做**（`toMarkdown`）。它和 `scripts/export_report_md.py` 不是
   一个东西：脚本读的是业务库 + checkpoint 终态，能给出五维评分、配额表和 trace；页面只拿得到
   `InterviewOut` 那几列，导出的是"题干 + 答案 + 考察点 + 打分标准 + 追问 + 依据出处"的面试用卷。
6. **API 根地址可选**，默认同源。第二个候选值是给"页面用别的方式打开、API 单跑"的调试场景。

## 理由

- 同源挂载免掉了 CORS：`configs/development.yaml` 的 `cors_origins` 只有
  `http://localhost:3000`，走"另起一个静态服务器"的方案就得改配置或改代码，
  而改配置属于部署差异、改代码属于为页面破坏既有约定，两者都比挂载更贵。
- 零构建是这台机器的现实，也是"学习优先"的口径：页面要能被直接读通，
  不该让读它的人先去理解一个打包器。
- 挂载点选在 `/`，`/api/v1` 保持不变，测试里两条用例把"两边都通"和"目录缺席不挂载"钉住。

## 权衡与代价

- **没有鉴权**。页面上的按钮对任何能访问该端口的人都有效，比 `curl` 更容易误触。
  认证欠账本来就挂在 `docs/TODO.md`（所有表都没有 `user_id`），这里不新增理由，只是让它更显眼。
- **没有分页**。列表一次拉 100 条，超过就看不见。库里现在 12 份简历 / 9 份报告，够用。
- **`GET /jobs` 拿不到 JD 正文**，所以页面无法展示"这份报告是按哪句 JD 出的题"，
  只能显示报告里每道题的逐字依据。要补的是 `JobOut`，不是页面。
- **`interview` 为空名简历显示文件名**。`run_e2e_live.py` 那条链路不回写 `resume.name`，
  页面按 `name || file_name || id` 兜底，标题就落回 `附件简历-梁清生.pdf`。
- **空报告不止一种成因**（2026-10-24 起改按 `status` 分，见 ADR-0015）。以前 `running` /
  质量门判死 / 后台任务失败三种都长得一样，页面只能靠"批注有无"去猜服务端语义。
  门拆掉之后 `review` 恒落 `completed`，剩下的三种成因在 `status` 上是可分的：
  `running` = 还在跑，`completed` + 0 题 = 收尾拿到空批次，`aborted` = 没跑到收尾。
  页面因此不再猜了。理想形状仍然是 `interview` 上有一个终止原因字段——批注现在只说
  "哪几题有问题"，不再说"为什么没有题目"。
- 静态目录进了仓库，`project_structure.md` 现在又少一项描述（那份文档本来就已过时）。

## 后续影响

- `create_app()` 从此不只是 API 工厂；新增挂载/静态目录相关行为要在
  `tests/test_api/test_m6_api.py` 末尾那两条用例上体现。
- 若将来真的引入构建工具（或换 React/Vue），替换的是 `frontend/` 目录内容，
  `main.py` 里那三行挂载不动。
- 页面验证只能靠浏览器：本轮实测走 `browser-use`，路径为
  `http://127.0.0.1:8000/` → 生成 / 简历库 / 报告列表 / 岗位四个视图，
  以及一次真实发起出题（上游 402，页面按失败分支显示 `llm_error` 与 `HTTP 402`）。
