# ADR-0015：评审退回为纯批注——删掉 `review → generate` 回退边，一次成卷、题目必落库

## 背景

触发点是一份真跑出来的报告（`61dc1bd9ed95…`）：**状态"已中止"、题目 0 道、评审批注 5 条**。
库里那 11 份历史报告里 8 份是同一形状。看的人得到的信息是"什么都没生成"，
而实际发生的是：`generate` 三轮各造满 15 题，`review` 三轮各挑出 5-6 条硬伤，
按 ADR-0010 的"预算用尽一行题目都不写"把 45 道题全丢了。

追下去有三层问题，只有第一层是"阈值调不准"：

1. **回退拿不到反馈**。`GenerateJob` 的载荷里没有 `review_issues`（ADR-0010 的载荷清单是
   `plan_item / raw_text / jd_text / parsed / roster / order_start / question_batch`），
   所以重做不是"照着批注改"，而是**用同一个 prompt 在同一批槽位上盲重掷**。
   实测三轮的毛病同类复现——换皮重复还是换皮重复，只多烧两遍 token。
2. **判据本身就偏**。`fail_ratio = 批注条数 / 题目数`，分子是条数不是"有问题的题数"：
   模型对同一题报两条算两个缺陷，缺题按条记（这是 ADR-0010 为了"门关得上"特意定的）。
   15 题里 5 条批注 = 0.33 > 0.3 就整批判死，可那 5 条里有 3 条只指向 2 道题。
3. **产品不接受这个终局**。维护者的要求是一句话："先生成完整的题目，质量节点只做输出哪些
   题目有问题，而不是直接不让题目生成。"拦门的代价（一份 0 题的报告）远高于它的收益
   （一次没有反馈的重掷）。

## 决策

| 环节 | 选择 | 被否决的方案 |
|---|---|---|
| 图形状 | `review` 是终点：`add_edge(REVIEW, END)`，删 `route_after_review`。剩下的回退边只有 `validate → parse` 一张 | 保留回退但把批注装进 `GenerateJob`（"定向重做"是另一件事，见后续影响；这次先把交付物还给人） |
| 终态 | 跑到收尾就 `completed`，批注多少条都一样。`aborted` 只剩一条来路：后台任务中途崩（`tasks/question_generation.py`） | 继续用 `aborted` 表示"质量不合格"（它现在的意思就是"没跑到收尾"，两种语义挤一个状态值是要改表结构的，不值） |
| 配置 | 删 `agent.review_max_retries` 与 `agent.review_fail_ratio_threshold`（`AgentParams` + 三份 yaml 一起删） | 留着但不读（留着不读的配置项是下一颗雷） |
| state 通道 | 删 `review_retries`；`review_issues` 降为**纯观测通道** | 保留计数通道当"历史痕迹"（checkpoint 与 `task.progress` 已经是痕迹，不必在 state 里再留一个没人写的整数） |
| 判据函数 | 删 `should_redo` / `fail_ratio`。AGENTS.md §4.9"质量门判据只写一处"随之下线，剩下的一句是"批注的采纳判据只写一处"（`adopt_model_issues`） | 留一个恒返回 False 的 `should_redo`（契约测试会继续断言一个不存在的门） |
| 规则层短路 | 撤掉。规则批注再多也照问模型 | 沿用"规则已超阈值就不调模型"（那是为省钱拦门服务的；现在批注不拦门，这一轮是这批题**唯一**一次语义检查，跳过等于交付一份只做过机械检查的卷子） |
| 空批次 | 不拦门也不花钱：跳过语义评审，按 `plan.total` 记缺题批注，仍然落 `completed` | 算 `fail_ratio = 1.0`（那个函数的定义域没了） |
| 评审模型挂掉 | 吞成一条 `index=None` 的批注 + 一行流水账，**题目照落** | 原样重抛 `LLMError`（ADR-0010 §"评审失败必须重抛"）。重抛在今天等于"评审一坏，整份卷子变 0 题"，比交一份只做过规则检查的卷子更糟 |
| 落库签名 | `persist_report(...)` 不再收 `status`，内部固定写 `completed`；幂等仍靠 `latest_batch(interview_id) != batch` | 保留 `status` 参数（只剩一个取值的服务层参数是纯装饰） |
| 展示 | 列表行加"N 条批注"黄徽章；详情页把被点名的题加 `.question.flagged` 边框与就地批注块；Markdown 导出每题标题带批注数 | 只给一个总条数（15 题里 3 条批注，看的人不知道是哪 3 题，等于没给） |
| 表结构 | **不动**：`interview.status` 的 CHECK 约束、`question.batch` 与 `(interview_id, batch, order_index)` 唯一约束原样留着 | 加一个 `needs_attention` 状态值（给 CHECK 加取值要重建表，正撞 ADR-0013 明令禁止的 `batch_alter_table`，而它曾经级联删空过 30 行题目） |

## 理由

1. **一次成卷是"批注有用"的前提**。批注要起作用，看报告的人必须同时看见题目和批注；
   判死之后批注孤零零挂在一份 0 题的报告上，它连被读的机会都没有。
2. **盲重掷没有正期望**。回退要能收敛，反馈必须进载荷；反馈没进去之前，重试只是把同一枚
   骰子再摇一次，还多花一轮扇出的钱（实测一轮 11 次调用、约 13.7 万 prompt token）。
3. **"哪几题有问题"是人能执行的输出，"整批不合格"不是**。前者告诉面试官跳过第 5、7、15 题，
   后者只告诉他今天没有卷子。
4. **质量判断的归属变了**：从"门决定这批题能不能交付"变成"标注出来，人决定用不用"。
   这是把一个模型给的分数当成终审，换成一个模型给的注脚——后者错了代价小得多。
5. **不动表结构是这次改动最重要的约束**。删掉回退已经够大了；为一个状态值去重建 `interview`
   表，风险与本 ADR 想解决的问题（少丢交付物）不成比例。

## 权衡与代价

- **一份卷子里可能留着模型自己都不满意的题**。这是本次决策的全部代价，也是它的目的。
  缓解手段是展示层的点名（列表徽章 + 详情页边框），不是拦门。
- **成本护栏只保一轮扇出**。以前"越线重做"天然限制了总调用数，现在 `max_tokens_per_run`
  就是唯一那道闸；一次成卷的用量约等于旧逻辑的第一轮，省下的钱正好是被删掉的重试。
- **`question_batch` 恒为 1**。多批次机制（`Overwrite`、`latest_batch`、`batch` 列与它的
  唯一约束）现在没有第二个写入者，成了休眠代码。留下的理由：① 拆它要动表；
  ② 定向重做如果以后落地会直接用上；③ `Overwrite` 那条"累积通道必须整批换掉"的失效模式
  仍由 `test_m5_pipeline.py` 拦住，替将来重新引入批次保序。
- **空报告的解释权从"批注有无"移交给 `status`**。ADR-0012 里"页面靠批注把三种成因分开"
  这段不再成立，前端已改成按 `status` 分支：`running` = 还在跑，`completed` + 0 题 = 收尾
  拿到空批次，`aborted` = 没跑到收尾。
- **`AGENTS.md` §4.4 的那条"不要 except 后返回空结果——质量门会误判为通过"失去了一半适用面**。
  门没了，但前半句仍然成立，而且更成立：现在吞掉异常必须**同时留下一条批注**，
  否则"语义检查没做完"这件事就没有任何地方记录它。`review_node` 里那条 `index=None` 的批注
  就是为这句话存在的。
- **`review_issues` 的 `origin` 归因价值上升**。以前它只解释门为什么关上，现在它是面试官
  唯一的风险提示来源；规则类批注复现说明毛病在配额表，模型类复现说明毛病在出题模板。
